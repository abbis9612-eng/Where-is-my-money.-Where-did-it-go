## 1. الهدف وقياس النجاح

**الهدف:** العائلة تعرف وين يروح كل دينار خلال 30 يوم، وتبدي تدّخر من أول راتب.

| المقياس | الهدف بعد 3 أشهر من الاستخدام |
|---|---|
| نسبة الصرف المسجّل من الدخل | ≥ 90% |
| زمن تسجيل عملية | ≤ 5 ثواني (يدوي)، ≤ 3 ثواني (صوت) |
| الادخار الشهري | > 0 بكل شهر |
| جلسة الجمعة | ≥ 3 من 4 أسابيع |

## 2. خارج النطاق الآن
ربط مباشر بالبنوك (غير متاح بالعراق)، استثمار، قروض، آيفون (لاحقاً — الكود جاهز له)، قراءة الوصولات بالكاميرا، مسابقات ونقاط.

## 3. المستخدمون والأدوار

- **المستخدم:** أي شخص يسجّل بالبريد الإلكتروني.
- **العائلة (Household):** مساحة مشتركة. المستخدم ممكن يكون عضو بأكثر من عائلة (مثلاً بيته + بيت أهله).
- **الأدوار:** `owner` (يدير الأعضاء)، `member` (يسجّل ويشوف كل شي)، `viewer` (للطفل لمن يكبر — يشوف أهدافه فقط) — ‏viewer بالمرحلة 2.
- **المصروف الحر:** لكل عضو ظرف خاص اسمه "مصروفي الحر"؛ العائلة تشوف **المبلغ الكلي** بس، مو التفاصيل (مبدأ من البحث: شفافية + خصوصية شخصية).

## 4. المفاهيم الأساسية (نموذج البيانات)

| الكيان | الوصف | حقول أساسية |
|---|---|---|
| `households` | العائلة | `id, name, base_currency (IQD), created_by` |
| `members` | عضوية مستخدم بعائلة | `household_id, user_id, display_name, role` |
| `wallets` | مكان الفلوس | `name, kind (cash/qi_card/mastercard/zain_cash/bank/other), currency (IQD/USD), opening_balance, owner_member_id?` |
| `categories` | تصنيف الصرف/الدخل | `name, icon, kind (expense/income), group (needs/wants/savings), is_default` |
| `envelopes` | ظرف/هدف | `name, kind (sinking/goal/free_money/locked), target_amount, target_date, monthly_amount, locked_until, image?` |
| `transactions` | عملية | `kind (expense/income/transfer), amount_minor, currency, wallet_id, to_wallet_id?, category_id?, envelope_id?, fx_rate_to_base, occurred_at, note, source (manual/voice/sms), created_by_member` |
| `fx_rates` | سعر صرف يومي يدخله المستخدم | `date, usd_to_iqd, source (official/market/manual)` |
| `paydays` | سجل "ادفع لنفسك أولاً" | `income_tx_id, saved_amount, allocations` |

**ثوابت (Invariants):**
1. المبالغ تُخزّن **أعداداً صحيحة بالوحدة الصغرى** (`amount_minor`): الدينار بلا كسور (1 = 1 دينار)، الدولار بالسنت (1 = 0.01$). **لا `double` للمال أبداً.**
2. كل عملية بعملة غير عملة العائلة تحفظ `fx_rate_to_base` **وقت العملية** — تقارير الماضي لا تتغير لمن يتغير سعر الصرف.
3. التحويل بين محفظتين = عملية واحدة `transfer` (مو صرف ودخل) حتى ما يتضخم الصرف.
4. لا حذف فعلي: `deleted_at` (حذف ناعم) — ضروري للمزامنة.
5. كل صف له `id` من نوع UUIDv7 يتولّد على الجهاز (يشتغل بدون إنترنت).

## 5. الشاشات والتدفقات (المرحلة 1)

1. **أول تشغيل:** اختيار: "ابدأ بدون حساب" (محلي) أو "سجّل دخول" (مزامنة). إنشاء العائلة + محافظ افتراضية (كاش دينار، كاش دولار، كي كارد) + التصنيفات العراقية.
2. **الرئيسية:** "المسموح هذا الأسبوع" (رقم كبير + مدى)، أزرار سريعة: ➖ صرف، ➕ دخل، 🎙️ بالصوت، آخر العمليات، تنبيه "يوم الراتب؟".
3. **إضافة سريعة:** لوحة أرقام كبيرة → تصنيف (أكثر 8 استخداماً أولاً) → حفظ. ≤ 3 لمسات.
4. **بالصوت:** "صرفت عشرين ألف مولدة" → مبلغ 20,000 + تصنيف المولدة → تأكيد.
5. **يوم الراتب (ادفع لنفسك أولاً):** لمن ينسجل دخل من نوع راتب → شاشة: كم تدّخر أولاً؟ (اقتراح 10%) → توزيع على الظروف → الباقي = ميزانية الشهر → المسموح الأسبوعي.
6. **الظروف:** قائمة + تقدّم كل ظرف + تمويل/سحب.
7. **التقرير الشهري:** وين راحت الفلوس (حسب التصنيف/العضو/المحفظة)، مقارنة بالشهر الماضي، أكبر 5 "تسريبات".
8. **جلسة الجمعة:** 3 أسئلة + ملخص الأسبوع + تعديل الأسبوع الجاي.
9. **الإعدادات:** العائلة والأعضاء والدعوة، المحافظ، التصنيفات، سعر الصرف، القفل بالبصمة، تصدير CSV، حذف الحساب.

**الحالات لكل شاشة:** تحميل، فارغ (مع خطوة أولى واضحة)، محتوى، خطأ، بدون إنترنت (يشتغل عادي + مؤشر "بانتظار المزامنة").

## 6. منطق "المسموح هذا الأسبوع"

```
ميزانية_الشهر = الدخل المتوقع − الادخار أولاً − تمويل الظروف − الالتزامات الثابتة
المسموح_الأسبوعي = (ميزانية_الشهر المتبقية) ÷ (الأسابيع المتبقية بالشهر)
المعروض = المسموح_الأسبوعي − صرف_الأسبوع، يُعرض مع هامش أمان 10% (البحث [5]: الرقم الدقيق يشجع الصرف لحد الحد)
الباقي آخر الأسبوع ينتقل للأسبوع الجاي (البحث [5]: تذكير الترحيل يقلل التسارع)
```

## 7. قرارات المعمارية (ADRs)

### ADR-1: Flutter لتطبيق الموبايل
- **القرار:** Flutter (الإصدار المستقر 3.47).
- **ليش:** كود واحد لأندرويد الآن وآيفون لاحقاً؛ دعم RTL ممتاز؛ ‏Dart قوي بالأنواع.
- **البدائل:** Kotlin Multiplatform (أقوى لمنطق أندرويد، بس واجهتين)؛ React Native (لا ميزة حاسمة).
- **نرجع عنه إذا:** صار الشغل الأصلي لأندرويد (الرسائل، خدمات الخلفية) أكثر من ثلثين المنتج.

### ADR-2: محلي أولاً بقاعدة SQLite (Drift) مشفّرة
- **القرار:** كل البيانات بقاعدة SQLite محلية عبر Drift، مشفرة بـ SQLite3MultipleCiphers (مدعوم رسمياً بـ Drift ≥ 2.32)، والمفتاح بـ Android Keystore عبر `flutter_secure_storage`.
- **ليش:** يشتغل 100% بدون إنترنت (الكهرباء والنت مو مضمونين)، تقارير سريعة بـ SQL، والبيانات المالية محمية لو انسرق الموبايل.
- **البديل:** Firestore بكاش محلي — رفضناه لأن التقارير والتجميع محدودة واحتكار المورد أعلى.

### ADR-3: Supabase (Postgres) للمزامنة والحسابات
- **القرار:** Supabase: ‏Auth (بريد إلكتروني برمز OTP)، Postgres مع **Row Level Security** يعزل كل عائلة، ومزامنة عبر REST.
- **ليش:** SQL حقيقي لمنتج مالي، عزل العائلات على مستوى قاعدة البيانات، مفتوح المصدر وقابل للاستضافة الذاتية (ما نصير رهائن مثل مستخدمي Mint).
- **التكلفة:** مجاني حتى مشروعين، 500MB، 50,000 مستخدم شهرياً؛ **المشاريع المجانية تتوقف بعد أسبوع بدون نشاط**؛ Pro من 25$ شهرياً (supabase.com/pricing، تم التحقق 12/10/2026). استخدام عائلي يومي يكفي لإبقائه نشطاً؛ عند الإطلاق العام ننتقل لـ Pro.
- **البدائل:** Firebase (مزامنة جاهزة، بس NoSQL واحتكار)؛ PowerSync (مزامنة احترافية، بس خدمة إضافية بكلفة) — نرجع له إذا صار عندنا تعارضات مزامنة حقيقية كثيرة.

### ADR-4: بروتوكول المزامنة
- **دفع (Push):** الصفوف المحلية اللي `dirty = 1` تنرسل بـ upsert. السيرفر يضع `server_updated_at = now()` تلقائياً (trigger).
- **سحب (Pull):** كل جدول: `server_updated_at > آخر_مؤشر` مرتبة تصاعدياً، بدفعات.
- **التعارض:** آخر تعديل يفوز على مستوى الصف حسب `updated_at` (ساعة الجهاز) — مقبول لأن العمليات المالية تنضاف أكثر مما تتعدل. الحذف ناعم فما يضيع شي.
- **الأمان:** RLS: المستخدم يقرأ ويكتب بس صفوف العائلات اللي هو عضو بيها.

### ADR-5: الإدخال بالصوت
- **القرار:** محرّك التعرف على الكلام بالجهاز (`speech_to_text`، لغة `ar-IQ` مع رجوع لـ `ar`) + **محلل نصوص عراقي مكتوب بـ Dart** (أرقام بالكلمات: "عشرين ألف"، "ربع مليون"، "مية وخمسين"، "ورقة" = 100 دولار بالعامية… ومطابقة التصنيف بكلمات مفتاحية).
- **ليش:** مجاني، يشتغل بدون سيرفر، قابل للاختبار 100%. الذكاء الاصطناعي السحابي اختياري لاحقاً للحالات الصعبة.

### ADR-6: رسائل كي كارد (المرحلة 2)
- **يحتاج:** عينات حقيقية من رسائل كي كارد والمصارف (مع إخفاء الأرقام) + تصريح Google Play لصلاحية الرسائل.
- **البديل الفوري:** "شارك الرسالة مع التطبيق" (Share intent) — ما يحتاج صلاحية خاصة.

## 8. الأمان والخصوصية
- قاعدة بيانات مشفرة على الجهاز + قفل بالبصمة (اختياري).
- اتصال HTTPS فقط؛ مفتاح Supabase العام (anon) فقط بالتطبيق — **لا مفاتيح سرية بالكود**؛ الحماية الحقيقية بـ RLS.
- تصدير كامل (CSV) وحذف الحساب والبيانات بضغطة.
- لا إعلانات ولا بيع بيانات. لا تحليلات طرف ثالث بالنسخة الأولى.

## 9. معايير القبول (المرحلة 1)
1. بدون إنترنت: إضافة صرف/دخل/تحويل وتعديلها وحذفها تشتغل وتنحفظ بعد إعادة التشغيل.
2. "صرفت عشرين ألف مولدة" → 20,000 د.ع، تصنيف "مولدة".
3. صرف 50$ بسعر 1520 يظهر بالتقرير 76,000 د.ع ويبقى كذا حتى لو تغيّر سعر الصرف بعدين.
4. تسجيل راتب → تظهر شاشة "ادفع لنفسك أولاً" → الادخار ينخصم قبل حساب المسموح الأسبوعي.
5. عضوان بنفس العائلة على جهازين: عملية من الأول تظهر عند الثاني بعد المزامنة؛ مستخدم من عائلة ثانية ما يشوفها (RLS).
6. الواجهة كلها RTL وعربية، والأرقام تنعرض بفواصل الآلاف.

## 10. التحقق
- اختبارات وحدات لمنطق المال (الحسابات، الصرف، المسموح الأسبوعي، محلل الصوت).
- اختبارات قاعدة البيانات (Drift بالذاكرة).
- اختبارات واجهة للتدفقات الرئيسية.
- `flutter analyze` بدون أخطاء.
- CI على GitHub يبني APK للتحميل والتجربة على الموبايل.
- اختبار سياسات RLS على Supabase بمستخدمين مختلفين قبل الإطلاق العام.
